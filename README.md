# Umbra

Личная картотека фильмов и сериалов. Каталог доступен без входа; полка, оценки и заметки принадлежат аккаунту Firebase и синхронизируются между устройствами.

Это самостоятельный репозиторий и приложение, не часть CodeQuest.

## Запуск

Node.js 22.12+ (версия для CI в `.nvmrc`):

```sh
npm ci
npm run dev
```

Для проверки production: `npm run build && npm run preview`.

## Авторизация и личные данные

- Email/password и Google. Восстановление пароля доступно на экране входа.
- Единственный источник состояния входа — Firebase observer; localStorage не подтверждает сессию.
- Документы: `users/{firebaseUid}/library/{movie|tv}-{tmdbId}`.
- `onSnapshot` получает актуальную полку, включая удаления; библиотека другого пользователя никогда не объединяется с текущей.
- Firestore IndexedDB persistence с поддержкой нескольких вкладок сохраняет offline-очередь. При недоступном IndexedDB SDK может перейти на память; для критичных изменений дождитесь подтверждения облака.
- Изменения оценки/заметки отправляются как отдельные поля. Для одновременных изменений одного поля используется последний принятый сервером write; отдельные поля не перезаписываются целиком. Сервер задаёт время обновления.
- Личные заметки не являются публичными комментариями.
- После выхода подписка закрывается и полка скрывается. Локальный кэш SDK и черновики могут оставаться на устройстве; выход не обещает физического удаления данных с диска.
- Старый `umbra.library` автоматически не переносится: владелец этой общей копии неизвестен. В настройках есть отдельный экспорт старой полки; пользователь проверяет файл и импортирует его в нужный аккаунт.
- Импорт проверяет весь файл перед записью, добавляет/обновляет записи, не удаляет остальные. Большой импорт состоит из атомарных пакетов по 100 записей; после сетевой ошибки его можно повторить. Экспортируйте текущую полку перед импортом, если нужно сохранить прежние версии заметок.

Firebase web-конфигурация публичная. Защита данных обеспечивается `firestore.rules`, а не сокрытием API key. Разрешены только операции владельца и валидные поля. Правила нужно публиковать отдельно от Pages:

```sh
npx firebase deploy --only firestore:rules --project umbra-18ba8
```

В Firebase Authentication должны быть включены Google и Email/Password. Authorized domains: `kovalenkoserhii2107-maker.github.io` (и localhost для разработки). Google использует popup из нажатия кнопки, без принудительного cross-origin redirect на iPhone. При блокировке окна показывается ошибка; email остаётся альтернативой. Реальные OAuth-переходы в Safari/установленной iOS PWA нужно проверить вручную на устройстве.

## Обновления и PWA

Единственный production-артефакт — каталог `dist`. В GitHub Pages выберите **Source: GitHub Actions**. Workflow проверяет код и публикует `dist` после merge в main. Не публикуйте корень исходников и не коммитьте собранные `assets` обратно в main.

Vite назначает файлам content hashes. Service worker сохраняет согласованный комплект HTML/JS/CSS, проверяет обновления при возвращении в приложение и раз в минуту. Готовая версия появляется с кнопкой «Обновить»; она не перезагружает экран посреди редактирования. Ручной сброс Cache Storage и query-параметры версий не нужны. Настройки позволяют запустить проверку вручную. Номер сборки — короткий Git SHA.

Кэшируются оболочка и до 200 постеров. TMDB API использует ограниченную очередь, timeout, дедупликацию и короткий кэш в памяти. Данные Firebase не проходят через service worker. Offline-каталог не обещает полноту: доступны ранее сохранённая полка и кэш оболочки, а поиск требует сети.

## Проверки

```sh
npm test
npm run test:rules
npm run build
npm run test:e2e
```

Для эмулятора Firestore нужна Java 21. Для браузерных тестов: `npx playwright install chromium`. Тесты используют локальные Authentication/Firestore emulators, не рабочую базу. Firebase CLI входит только в devDependencies. `npm audit --omit=dev` проверяет поставляемые зависимости; известные предупреждения CLI не означают уязвимость клиентского bundle.

Проверяются: отсутствие чужих данных, отклонение невалидных документов, регистрация и повторный вход, синхронизация двух устройств, offline-правки, удаления, смена аккаунтов, устаревший профиль, production entry и PWA offline shell.

## Будущие уведомления

`status: watchlist` уже определяет интерес пользователя к фильму. Уведомления пока не отправляются. Для следующего этапа нужны отдельные пользовательские подписки/согласие, часовой пояс и канал (push/email), серверная проверка дат релиза по расписанию, идемпотентный журнал отправок и отмена подписки. Не запускайте отправку только из браузера: закрытое приложение её не выполнит. Данные подписок должны иметь те же ограничения по UID.

Данные каталога: TMDB; внешние рейтинги — Agregarr/IMDb-подборки. При недоступности IMDb-подборки не подменяются рейтингом TMDB под прежним заголовком.

This product uses the TMDB API but is not endorsed or certified by TMDB.
