# Umbra

Личная картотека фильмов и сериалов. Каталог открывается только после входа или регистрации: без аккаунта любой адрес ведёт на экран входа, а после входа пользователь возвращается на запрошенную страницу. Полка, оценки и заметки принадлежат аккаунту Firebase и синхронизируются между устройствами.

Это самостоятельный репозиторий и приложение, не часть CodeQuest.

## Запуск

Node.js 22.12+ (версия для CI в `.nvmrc`):

```sh
npm ci
npm run dev
```

Для проверки production: `npm run build && npm run preview`.

## Авторизация и личные данные

- Email/password и Google. Восстановление пароля доступно на экране входа.
- Единственный источник состояния входа — Firebase observer; localStorage не подтверждает сессию.
- Документы: `users/{firebaseUid}/library/{movie|tv}-{tmdbId}`.
- `onSnapshot` получает актуальную полку, включая удаления; библиотека другого пользователя никогда не объединяется с текущей.
- Firestore IndexedDB persistence с поддержкой нескольких вкладок сохраняет offline-очередь. При недоступном IndexedDB SDK может перейти на память; для критичных изменений дождитесь подтверждения облака.
- Изменения оценки/заметки отправляются как отдельные поля. Для одновременных изменений одного поля используется последний принятый сервером write; отдельные поля не перезаписываются целиком. Сервер задаёт время обновления.
- Личные заметки не являются публичными комментариями.
- После выхода подписка закрывается и полка скрывается. Локальный кэш SDK и черновики могут оставаться на устройстве; выход не обещает физического удаления данных с диска.
- Старый `umbra.library` автоматически не переносится: владелец этой общей копии неизвестен. В настройках есть отдельный экспорт старой полки; пользователь проверяет файл и импортирует его в нужный аккаунт.
- Импорт проверяет весь файл перед записью, добавляет/обновляет записи, не удаляет остальные. Большой импорт состоит из атомарных пакетов по 100 записей; после сетевой ошибки его можно повторить. Экспортируйте текущую полку перед импортом, если нужно сохранить прежние версии заметок.

Firebase web-конфигурация публичная. Защита данных обеспечивается `firestore.rules`, а не сокрытием API key. Разрешены только операции владельца и валидные поля. Правила нужно публиковать отдельно от Pages:

```sh
npx firebase deploy --only firestore:rules --project umbra-18ba8
```

В Firebase Authentication должны быть включены Google и Email/Password. Authorized domains: `kovalenkoserhii2107-maker.github.io` (и localhost для разработки). Google использует popup из нажатия кнопки, без принудительного cross-origin redirect на iPhone. При блокировке окна показывается ошибка; email остаётся альтернативой. Реальные OAuth-переходы в Safari/установленной iOS PWA нужно проверить вручную на устройстве.

## Обновления и PWA

Единственный production-артефакт — каталог `dist`. В GitHub Pages выберите **Source: GitHub Actions**. Workflow проверяет код и публикует `dist` после merge в main. Не публикуйте корень исходников и не коммитьте собранные `assets` обратно в main.

Vite назначает файлам content hashes. Service worker сохраняет согласованный комплект HTML/JS/CSS, проверяет обновления при возвращении в приложение и раз в минуту. Готовая версия появляется с кнопкой «Обновить»; она не перезагружает экран посреди редактирования. Ручной сброс Cache Storage и query-параметры версий не нужны. Настройки позволяют запустить проверку вручную. Номер сборки — короткий Git SHA.

Кэшируются оболочка и до 200 постеров. TMDB API использует ограниченную очередь, timeout, дедупликацию и короткий кэш в памяти. Данные Firebase не проходят через service worker. Offline-каталог не обещает полноту: доступны ранее сохранённая полка и кэш оболочки, а поиск требует сети.

## Проверки

```sh
npm test
npm run test:rules
npm run build
npm run test:e2e
```

Для эмулятора Firestore нужна Java 21. Для браузерных тестов: `npx playwright install chromium`. Тесты используют локальные Authentication/Firestore emulators, не рабочую базу. Firebase CLI входит только в devDependencies. `npm audit --omit=dev` проверяет поставляемые зависимости; известные предупреждения CLI не означают уязвимость клиентского bundle.

Проверяются: отсутствие чужих данных, отклонение невалидных документов, регистрация и повторный вход, синхронизация двух устройств, offline-правки, удаления, смена аккаунтов, устаревший профиль, production entry и PWA offline shell.

## Будущие уведомления

`status: watchlist` уже определяет интерес пользователя к фильму. Уведомления пока не отправляются. Для следующего этапа нужны отдельные пользовательские подписки/согласие, часовой пояс и канал (push/email), серверная проверка дат релиза по расписанию, идемпотентный журнал отправок и отмена подписки. Не запускайте отправку только из браузера: закрытое приложение её не выполнит. Данные подписок должны иметь те же ограничения по UID.

Данные каталога: TMDB; внешние рейтинги — Agregarr/IMDb-подборки. При недоступности IMDb-подборки не подменяются рейтингом TMDB под прежним заголовком.

Карточка фильма показывает три рейтинга: IMDb (Agregarr), TMDB (`vote_average`) и Rotten Tomatoes (Tomatometer). Tomatometer и Metascore (сводка рецензий критиков, которую IMDb показывает в разделе Critic reviews) берутся из OMDb по IMDb ID, а если OMDb не ответил или ключа нет — из Wikidata: у Rotten Tomatoes, Metacritic и IMDb нет публичного API, доступного из браузера. Если в Wikidata оценки нет, показывается «—». Полные тексты рецензий открываются ссылкой на страницу Critic reviews IMDb.

## Баннер главной

Баннер наверху главной персональный (`src/lib/spotlight.ts`), первое подходящее по порядку:

1. ближайший к сегодняшнему дню релиз из «Хочу посмотреть»;
2. новая серия или сезон сериала из коллекции (просмотрен или смотрю), вышедшие за последние 3 дня или выходящие завтра;
3. рекомендация TMDB по лучше всего оценённому просмотренному тайтлу, которого ещё нет в коллекции;
4. для пустой коллекции — популярная новинка недели.

В баннере есть кнопки «Хочу посмотреть» (если тайтла нет в коллекции) и «Трейлер». Показанный в баннере тайтл не повторяется в рядах ниже; ряд «Сейчас в кинотеатрах» показывается полностью.

## Релизы из «Хочу посмотреть»

Наверху главной показываются фильмы и сериалы из «Хочу посмотреть», которые выходят в ближайшие 7 дней или вышли за последние 7 дней (`DAYS_AHEAD`/`DAYS_BEHIND` в `src/lib/releases.ts`). Для фильма берётся первый публичный релиз в регионе из настроек (кинотеатр, цифровой, ТВ), иначе основная дата TMDB; для сериала — премьера сериала или нового сезона.

This product uses the TMDB API but is not endorsed or certified by TMDB.

## Отслеживание сериалов

Для сериала есть статусы «Смотрю» и «Бросил». В списке серий каждую серию можно отметить галочкой; прогресс хранится как последняя просмотренная серия (`season`/`episode` в документе полки), всё до неё считается просмотренным. Снятие галочки откатывает прогресс к предыдущей серии. На главной ряд «Продолжить смотреть» показывает следующую серию и кнопку «✓ Просмотрено» (`src/lib/tracking.ts`).

## Коллекция, статистика, «Поделиться»

- Фильтры коллекции: поиск, статус, тип, жанр, оценка, десятилетие и сортировка; состояние хранится в адресе страницы (`src/lib/collection.ts`). Жанры и длительность берутся из TMDB и кэшируются в `localStorage` на 30 дней (`src/lib/meta.ts`): в документах полки их нет.
- `/stats` — счётчики, часы просмотра (оценка по длительности и прогрессу), распределение оценок, жанры, годы выхода, лучшее; итоги по годам. Отдельной даты просмотра в полке нет, поэтому год считается по дате последней отметки.
- Кнопка «Поделиться» открывает выбор: Telegram, WhatsApp, Viber, «Сообщения», почта, копирование ссылки и системное меню (если есть). Ссылка ведёт на карточку в Umbra; без аккаунта получатель сначала попадает на вход и потом на эту карточку.

## Друзья

- `profiles/{uid}` — публичная карточка (имя и фото) для ссылок-приглашений; читается по ID любым вошедшим пользователем, перечислять профили нельзя.
- Приглашение: `#/friends/invite/{uid}`. Получатель добавляет приглашающего в `users/{me}/friends` и создаёт заявку `users/{them}/requests/{me}`; после «Принять» дружба взаимная.
- Друзьям видна копия полки без заметок: `profiles/{uid}/ratings/{type-id}`. Правила разрешают чтение, только если владелец добавил читателя в `users/{owner}/friends`. Копия обновляется клиентом, пока у пользователя есть друзья; удаление друга сразу закрывает доступ.
- **Новые правила нужно опубликовать** (`npx firebase deploy --only firestore:rules --project umbra-18ba8`). До этого раздел «Друзья» показывает ошибку доступа, остальное приложение работает как раньше: синхронизация копии и профиля не влияет на сохранение полки.

### Ключ OMDb

OMDb отдаёт свежие Tomatometer и Metascore, но нужен бесплатный ключ (https://www.omdbapi.com/apikey.aspx, 1000 запросов в день, результаты кэшируются на устройстве на сутки). Ключ попадает в клиент, как и ключ TMDB, поэтому это не секрет:

- для всех пользователей: GitHub → Settings → Secrets and variables → Actions → **Variables** → `OMDB_KEY`; workflow передаёт его в сборку как `VITE_OMDB_KEY`;
- для одного устройства: «Настройки» → «Rotten Tomatoes и Metacritic».

## Оценки друзей в каталоге

`FriendsIndexProvider` один раз загружает общие полки друзей и обновляет их при возвращении в приложение (не чаще раза в 2 минуты). На постерах в лентах и поиске значок с аватаром друга и его оценкой или статусом («хочет», «смотрит»); в коллекции — строка с оценками друзей; в карточке — ряд «Оценки друзей» рядом с рейтингами.

## Карточка фильма и сериала

Один запрос к TMDB (`append_to_response`: видео, актёры и группа, площадки, внешние ID, похожее, рекомендации, кадры, возрастные рейтинги/даты выхода) плюс OMDb. Видео и кадры запрашиваются на русском и английском (`include_video_language`, `include_image_language`).

- Шапка: оригинальное название, возрастной рейтинг региона (иначе США), статус сериала и тип, IMDb/TMDB с числом голосов, Rotten Tomatoes, оценки друзей.
- Награды (OMDb, переведены по шаблонам `src/lib/titleFacts.ts`; незнакомый формат показывается как есть).
- Где смотреть: подписка, бесплатно, с рекламой, аренда, покупка и ссылка «Все варианты» (данные JustWatch через TMDB).
- Даты выхода в регионе (премьера, кино, онлайн, диски, ТВ), все видео с выбором, кадры.
- «О фильме»: язык, страны, канал, создатели, студии, бюджет, сборы в мире (TMDB) и в США (OMDb), рейтинг MPA.
- Франшиза (`/collection/{id}`), композитор, оператор, монтаж, художник-постановщик, рецензии зрителей TMDB (на английском), рекомендации, ссылки (сайт, IMDb, TMDB, Wikidata, соцсети).

### Ключ TMDB

Ключи TMDB и OMDb в исходниках не хранятся: сборка берёт их из переменных репозитория `TMDB_KEY` и `OMDB_KEY` (GitHub → Settings → Secrets and variables → Actions → Variables) как `VITE_TMDB_KEY` и `VITE_OMDB_KEY`. Без `TMDB_KEY` каталог не загрузится. Для локальной разработки создайте `.env.local` (он в `.gitignore`):

```sh
VITE_TMDB_KEY=ваш_ключ_tmdb
VITE_OMDB_KEY=ваш_ключ_omdb
```

E2E-тесты подменяют ответы TMDB и подставляют тестовый ключ сами. Копия ключа, которую сохраняли прежние версии на устройстве, удаляется при запуске.
